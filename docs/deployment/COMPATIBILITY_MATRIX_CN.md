# 兼容性矩阵

本页帮助用户在安装前判断环境是否合适。它描述当前 v5 文档基线，不替代每个券商、交易所、模型或应用商店的地区和账户要求。

## 服务端与浏览器

| 环境 | 状态 | 建议 |
| --- | --- | --- |
| Windows 11 x86-64 + Docker Desktop/WSL 2 | 推荐用于个人与开发 | 16 GB 内存更适合并发 AI 和回测 |
| Windows 10 22H2 x86-64 | 支持 | 使用仍受支持的 Docker Desktop 与 WSL 2 |
| Ubuntu/Debian x86-64 + Docker Engine | 推荐用于生产 | 使用 Compose v2、固定镜像版本和 HTTPS |
| macOS + Docker Desktop | 支持个人与开发 | Apple Silicon 需使用提供多架构支持的镜像 |
| 其他 Linux 发行版或 ARM 服务器 | 条件支持 | 先在预发布环境验证全部镜像、数据库与券商 SDK |
| 当前 Chrome / Edge | 推荐 | 启用 Cookie、WebSocket 和 JavaScript |
| 当前 Firefox / Safari | 支持主要流程 | 升级前验证图表、下载和实时状态 |
| Internet Explorer | 不支持 | 使用现代浏览器 |

## 推荐硬件配置

以下是服务端与数据库部署在同一台机器时的起步建议。实际容量取决于历史数据量、并发回测、策略数量、用户数和日志保留周期。

| 使用场景 | CPU | 内存 | 可用磁盘 | 建议用途 |
| --- | --- | --- | --- | --- |
| 最低体验环境 | 4 核 x86-64 | 8 GB | 30 GB SSD | 单用户体验、少量数据和短回测，不建议实盘 |
| 个人日常使用 | 6–8 核 | 16 GB | 100 GB SSD | AI 投研、常规回测、少量模拟策略 |
| 小团队或实盘 | 8–12 核 | 32 GB | 200 GB 以上 SSD | 多用户、持续任务、多个策略与生产监控 |
| 大规模回测或研究 | 16 核以上 | 64 GB 以上 | 500 GB 以上 NVMe | 并发回测、大标的池、长历史数据 |

CPU 应支持 64 位虚拟化。数据库、消息队列和回测会持续写盘，优先使用 SSD/NVMe，不建议把生产数据卷放在机械硬盘、临时盘或网络同步目录中。磁盘使用率达到 70% 前应扩容或调整日志与历史数据保留策略。

### Docker 资源分配

- Windows/macOS 的 Docker Desktop 至少分配 4 核、8 GB 内存；日常使用建议 6 核、12 GB 以上。
- 为宿主系统保留至少 2 核和 4 GB 内存，不要把全部资源分配给 Docker。
- Linux 生产环境应配置足够的交换空间应对短时峰值，但不能用交换空间替代实际内存。
- 多用户或高并发场景应将 PostgreSQL 数据放在独立持久卷，并监控磁盘延迟、连接数和增长速度。

### GPU 是否必需

QuantDinger 服务端、Web、回测和云端模型 API 不要求 GPU。只有在同一主机运行本地大模型、GPU 数据处理或自定义推理服务时才需要独立显卡；显存需求由所选模型决定，本地模型资源不应挤占数据库和交易运行时的保留容量。

### 网络与时间

- 首次安装需要访问 GitHub/GHCR 和所配置的外部服务；受限网络应提前配置可信代理。
- 公网生产环境建议稳定的有线网络、固定域名、HTTPS 和可用的 DNS。
- 券商、交易所、OAuth 和签名接口依赖准确时间，应启用 NTP 时间同步。
- 除 80/443 或明确需要的入口外，不应向互联网暴露数据库、Redis、Kafka 和后端内部端口。

## 客户端

| 客户端 | 依赖 | 说明 |
| --- | --- | --- |
| 桌面 Web | QuantDinger 服务端 | 完整管理、研究、回测与交易界面 |
| 移动 H5 | 可从手机访问的服务端 URL | 适合浏览器使用，不是独立后端 |
| Android / iOS 包 | 已配置公开 HTTPS API 的服务端 | 构建、签名与商店发布按[移动端部署](MOBILE_CLIENT_DEPLOYMENT_CN.md)执行 |

## 外部服务兼容原则

- 券商能力受账户类型、地区、市场权限、模拟/实盘环境和 SDK 版本影响。
- AI 模型名称和端点会变化，应以“系统设置 → AI / LLM”的连接测试为准。
- 数据源的频率、复权、时区、历史深度和授权并不相同。
- OAuth、邮件、短信和支付回调在生产环境应使用公开 HTTPS 域名。
- 本地桌面券商网关需要与容器网络互通，并限制为可信主机访问。

## 发布兼容性验收

每个版本至少验证：全新安装、从上一稳定版升级、数据库迁移、管理员登录、研究与回测、移动 H5、至少一个模拟券商、备份恢复、主流浏览器和回滚路径。尚未验证的组合应标记为条件支持，不能仅凭“能启动”宣称兼容。

发现兼容问题时，请附版本、操作系统、CPU 架构、Docker/Compose 版本、浏览器和已脱敏日志，并参考[错误知识库](ERROR_KNOWLEDGE_BASE_CN.md)。
