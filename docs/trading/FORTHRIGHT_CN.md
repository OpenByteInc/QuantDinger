# 方德证券 OpenAPI 接入

方德证券（Forthright）通过独立的证券、期货账户配置接入美股、港股和指定到期合约的期货。期权不支持。桌面端和手机端共用按用户隔离的 `/api/forthright` 接口。

## 连接与解锁

在账户页面填写一次 App ID、PKCS#8 Ed25519 或 RSA 私钥及交易密码，即可通过 `/account/list` 自动发现证券、期货子账户，并在同一个数据库事务中保存。每个子账户仍有独立的凭证 ID、交易路由与解锁状态，忽略期权账户。重新连接会按网关、App ID、交易账号、类别更新已有记录，测试与正式网关分别保存。登录账号与 API 交易账号可能不同。

连接表单支持固定网关选择：测试 `https://test-openapi-gw.techfx88.com`、正式 `https://openapi-gw.forthright-sec.com.hk`。新凭证单独保存 `gateway_environment`。没有此字段的旧凭证继续使用原部署网关（`FORTHRIGHT_GATEWAY_URL`，未设置时为测试网关），升级不会自动切换至正式网关。去重同时核对网关、应用、交易账号和类别；策略不能覆盖已保存凭证的网关。网关类型本身不代表账户是否使用真实资金，浏览器不能指定任意上游地址。

连接仅执行查询。交易前可使用账户页面的“解锁交易”。错误 `10003` 表示该账户类别需要短信二次认证，应在同一账户输入验证码。公开文档只有解锁和二次认证接口，没有独立的发送短信接口或送达回执；返回该错误不能证明短信已发送。收不到短信时，应请方德核对账户绑定手机及认证配置，不应重复下单触发短信。

## 交易与同步

- 证券支持当日有效的市价／限价单；美股数量最多四位小数。方德港股必须为该证券当前每手股数的整数倍，不支持碎股；预览及后端同时校验。价格和权限限制继续由券商校验。证券市价单需正数参考价。股票策略保持仅做多。
- 期货闪电交易从合约列表选择准确的 `prodCode`，数量使用整数手，支持市价／限价当日单。连续合约、过期或超过最后交易日的合约被拒绝，不自动换月。买卖作用于券商净持仓，可能平掉已有仓位。
- 策略沿用持久化订单队列、持仓归属、幂等订单标识和成交同步。期货支持多空方向；同一账户、同一合约的相反方向持仓归属会被拦截，不提供独立双向持仓。没有为期货开启加密货币杠杆设置或网格／马丁机器人。
- 接单回执不代表成交。超时或网关异常后进入查询核对，不盲目重发。只有明确的 `10005` 未解锁拒单允许解锁后使用相同标识重试一次。期货撤单从订单查询恢复 `extOrderId`、`accOrderNo`、合约和方向，支持进程重启后撤单。
- 期货成交均价取成交接口明确的十进制均价，并校验成交数量一致；不猜测整数 `totalTrdPrc` 的缩放比例。成交明细未到齐时继续等待同步。费用没有权威数据源时保持待确认，不当作已确认的零费用。
- 暂不支持券商附带止盈止损单，闪电交易隐藏对应入口。策略仍通过既有运行中的交易进程执行策略保护逻辑。

## 期货策略参数与行情

部署 `.env` 中的 `FORTHRIGHT_FUTURES_CONTRACT_SPECS` 是 JSON 对象。常规 Compose 部署已将该文件挂载给 API 和工作进程，修改后重启受影响进程。每个准确的券商 `prodCode` 应配置：

| 字段 | 含义 |
| --- | --- |
| `point_value` | 经核验的一手合约每点价值，正数，以结算币种计 |
| `currency` | `USD`、`HKD` 或 `CNY`，须与所选期货凭证的币种一致 |
| `data_provider` | `yfinance` 或 `twelvedata` |
| `data_symbol` | 行情源对应的准确到期合约代码，产品、到期日、币种和价格比例必须一致 |

每点价值、币种也可按券商品种代码 `instmntCode` 配置，但行情映射必须按准确的 `prodCode` 配置。保留已过期合约的历史参数，以便核对尚未入账的成交。不能将 `lotSize` 或 `tickSize` 直接当作每点价值，因此默认不填入未经核验的合约乘数和连续合约映射。

参数不完整或币种不符时会阻止部署。到期合约行情路径不会回退到加密货币、现货贵金属或连续期货。行情授权、可用性和时效仍需满足策略要求，配置映射不代表行情已验证。手动期货下单不依赖这些策略参数。

现有策略账本按“数量 × 价格”计值，所以期货策略数量使用“手数 × 每点价值”。例如核验乘数为 5 时，策略数量 10 对应 2 手，价格每变动一点，盈亏为 10 个结算货币单位。适配器向下取整为整数手，不提高预算；成交及持仓再转换回账本单位。闪电交易和券商账户页面显示的始终是实际手数。资金限制使用完整名义金额及杠杆 1，未建模交易所保证金表。

## 错误诊断与显示精度

响应首先按严格 UTF-8 解码，不依赖可能错误的 HTTP charset。只有错误响应含非法 UTF-8 字节时才尝试 GB18030；成功的资金和持仓数据不采用猜测编码。错误详情保留券商代码、脱敏原因、解码方式和响应本身是否已有替换字符。上游已替换为 `\uFFFD` 的文字无法可靠还原。私钥、交易密码、应用与账户标识、提交的验证码均会脱敏。通用错误 `10000` 仍按结果待确认处理，不自动重复下单；显示原因不等于确认拒单或成交。

方德美股输入最多四位小数，港股输入必须为整手股数的整数倍，并移除股票数量末尾无意义的零。股票闪电交易按委托币种查询资金，不再把美元总额直接标为港币。港股订单查询在过滤前将 `03690` 等图表代码规范为 `03690.HK`。


## 币种展示与授权记录

连接表单仅提供 USD、HKD 作为资产展示币种。证券 `fund_total.to_ccy` 仅折算汇总展示，不执行换汇，也不证明账户持有该币种现金。`fund_detail` 提供原币可用现金、已交收现金及可取金额，页面分开显示并保留负值。持仓和订单价格保留标的币种；零数量记录不计入当前持仓，未成交订单不显示虚假的成交均价。

手动授权成功的观察结果及时间保存在按用户隔离的加密凭证中，刷新页面后恢复。这代表最近一次成功验证，不代表券商授权永久有效；页面刷新不会调用解锁或发送验证码，实际交易仍以券商返回为准。

统一美元应限于报表展示：美股执行预算采用 USD，港股采用 HKD。方德按账户规则处理兑换，QuantDinger 使用总购买力，不发送换汇指令；不能根据折算后的汇总资产推断某笔换汇已经发生。期货策略部署关闭，预留的参数模型仍要求核验结算币种和每点价值。

### 2026-11-26 编码排查

历史期货下单诊断读取的是 `response.json()` 的顶层 `status` 和 `info`，不是原始 HTTP 字节。限价测试保存的字段为 `status=10000`、`info=service response failed: status=1 info=\uFFFD۸\uFFFD\uFFFD\uFFFD\uFFFD`；市价测试末尾为十个 `U+FFFD` 替换字符。

离线对照中，`价格错误` 的 GBK/GB18030 字节为 `bc db b8 f1 b4 ed ce f3`，误按 UTF-8 并采用替换错误处理时，恰好得到 `\uFFFD۸\uFFFD\uFFFD\uFFFD\uFFFD`。这是一个匹配的候选解释，不是从历史原始字节恢复的确证；替换解码是多对一映射。GBK、Big5、Latin-1 不能严格反向编码已有替换字符，GB18030 的反向编码也不能恢复原始 UTF-8 文本。不要把该候选文字当作券商确认的拒单原因，更不能因此自动重发订单。

本次只读复查期货 `fund_total`、`position`、`working_order`、`history_order`，均返回 HTTP 200、业务状态 0、`info=success`，响应声明 `application/json; charset=utf-8`。对这批纯 ASCII 响应分别使用 UTF-8、GBK、GB18030、Big5 和 Latin-1 均可解析，UTF-16LE 不能解析为 JSON；这些成功响应无法证明旧下单失败响应的实际编码。本次未提交新订单或重新解锁。

## 证券链路复核 — 2026-11-26

- 成交历史改为合并 `history_match` 和 `today_match`，不再只读取完全成交的订单，保留部分成交后撤单的实际成交。以交易日、市场、订单号和成交流水号去重；成交查询失败时明确报错，不用不完整订单列表掩盖失败。目前查询窗口为近 90 天，并非全部历史。
- 订单创建/更新时间读取 `curr_date/curr_time`、`last_curr_date/last_curr_time`；成交时间读取发生日期和 `business_time`。交易日可能与自然日不同，仅用于成交标识。文档没有明确这些时间的 UTC 偏移，因此保留券商本地时间，未臆造偏移；其他时区用户的显示仍需方德确认时间口径。
- `fare_amt` 是整张订单累计的**总交易费用**，不只是佣金。已成交或部分成交后撤单的终态订单，按原币记录一次；缺失费用、非终态预估费用保持待确认。券商逐笔成交响应不包含费用。成交接口按订单关联终态总费用，仅在去重后的完整成交集合与订单的标的、方向、币种、累计数量及金额一致时，按成交金额分摊。先分摊再分页，保留舍入余差，确保合计等于订单总费用；`fee_source=order_allocation` 明确表示订单费用分摊，并非券商逐笔费用。证据缺失、不完整或费用查询失败时继续显示成交，费用保持待确认。PC 与手机按费用原币展示。策略会继续核对部分成交后撤单且费用待确认的订单，将延迟费用同步到交易账本及对应的策略回调成交汇总，不新增成交数量、不重复计费。部署时需同步更新后端和交易 worker，再更新电脑及手机端。期货费用处理未改变。
- 持仓 `enable_qty` 映射为可卖数量，保留零值；PC 卖出数量计算改为优先读取该字段，手机已有兼容。PC 交易记录同时区分成交股数和成交金额，并兼容两种数量字段名。

## 已确认的港股整手规则 — 2026-11-26

用户已向方德确认：港股只接受整手，不接受碎股。此前只限制整数股的校验已被本节规则替代。美股数量精度保持原状；本次修改不代表所有美股标的均支持小数股成交。

`app/services/market/hk_board_lots.py` 读取[港交所官方证券列表](https://www.hkex.com.hk/eng/services/trading/securities/securitieslists/ListOfSecurities.xlsx)，使用港币股票、交易所买卖产品及 REIT 的正整数 Board Lot。每个进程缓存一小时，香港日期变化时刷新；发布日期超过七天或晚于当天的文件会被拒绝。刷新失败或标的未知时阻止下单，不使用过期规则，也不猜测为每手一股。本地 API 容器只读核验腾讯为每手 100 股、长和为每手 500 股；宿主机同时核验美团为每手 100 股。

`GET /api/forthright/instrument-rules?credential_id=...&symbol=00700.HK` 为 PC、手机端提供所选账户的规则。切换账户或标的后旧规则失效；后端在实际提交前独立检查整手，前端不能通过改数量绕过。其他券商的数量处理保持不变。

- 手动数量必须为每手股数的整数倍；非法输入直接提示，不静默修改。
- 按金额下单及策略执行使用 `floor(预算 / 价格 / 每手股数) × 每手股数`。股价 90 港币、每手 100 股时，1,000 港币不足一手；10,000 港币可买 100 股，委托名义金额 9,000 港币。手续费另计；市价单估算不保证最终成交价或支出上限。
- 策略卖出先限制到本策略持仓、券商实际持仓及可卖数量，再向下取整到整手。例如持有 137 股时最多卖出 100 股，剩余 37 股保留在账本中。不足一手时返回本地化原因，不向上补量，也不在未成交时标记已平仓。

验证：后端 264 项、PC 808 项、手机端 233 项测试通过，两端生产构建通过，PC 源码 lint 为零错误。新增文案覆盖 11 种语言，完整性及编码检查通过。本地 API 已更新并验证健康；本轮未提交新订单。内置浏览器控制连接不可用，未重复视觉验收。现有长期运行的交易工作进程未重启，工作进程侧改动仍需通过受控源码／镜像发布生效。

## 凭证安全检查 — 2026-11-26

券商凭证以 Fernet 密文保存在 `qd_exchange_credentials.encrypted_config`。运行时使用独立 `CREDENTIAL_ENCRYPTION_KEY` 解密，并保留旧版本会话密钥兼容逻辑。没有迁移与备份恢复方案时，不应直接轮换或删除凭证加密密钥。本地只读检查了 13 条凭证，全部为可解密密文；独立加密密钥已配置且至少 32 字节。这些结论针对本地环境，不代表尚未检查的线上部署。

凭证列表、券商账户与状态接口按当前登录用户隔离，只返回账户元数据。响应出口增加嵌套敏感字段过滤，覆盖私钥、交易密码、应用密钥、访问令牌、短信码及密文，并设置 `Cache-Control: no-store`。凭证及连接接口的异常不再直接返回或记录原始异常内容。策略字段脱敏补充券商专用字段别名；老虎、Webull 配置对象的字符串表示排除秘密字段。

PC 表单发送复制后的连接请求后即清理敏感输入，页面停用或销毁时再次清理；手机端保存成功和离开页面时清理，并移除可能含请求密钥的完整 Axios 错误控制台输出。PC 请求调试代码也不再输出登录令牌。这些措施减少应用保留的数据，无法抹除浏览器开发者工具的网络记录、扩展读取或 JavaScript 引擎中的内存副本。用户自己录入和提交的私钥仍能在该浏览器中查看。线上必须使用 HTTPS，并保护服务器、加密密钥和数据库备份。

175 项专项后端测试、6 项前端行为测试以及两端构建通过。本地 4 个经过身份验证的只读接口没有匹配到已保存的秘密值，且均返回 no-store。检查 8 份当前日志各自最新 8 MiB，未匹配到完整秘密值。PC、手机端源码与构建产物的模式检查未发现内嵌 PEM 私钥块，但不代表覆盖所有秘密格式和编码。本次未提交交易订单。本地 API 修补已加载，长驻 worker 与线上尚未发布。当前本地 JWT 签名密钥不足建议的 32 字节；为避免现有会话失效，没有直接轮换，应在受控发布时更换，同时保持独立凭证加密密钥不变。
